## 0.2.2 remaining-day regeneration / weighted multi-round planning

Overview replaces single-platform add with explicit plan_regenerate. Platform pages retain manual add. Regeneration bypasses cache/retry cooldown, clips rounds to now..local midnight, and preserves completed/executing/manual tasks and manual cancellations. Remaining daily capacity is enforced both before model IO and again atomically at commit, so a concurrent scheduler claim cannot exceed the round budget or be overwritten. Model failure leaves tasks unchanged. Unstarted overnight replacements preserve tomorrow's tail; other-day carried rounds are protected. Same-account overlapping automatic rounds are rejected; cross-platform overlaps remain possible.

User correction: a permission-window line is NOT a round. round_intervals expands every allowed window after rest subtraction into multiple bounded reference-duration candidates (session_minutes, default30); the model selects up to remaining daily_rounds across them. Source slot identities keep individual cancellations stable without blocking all other rounds in that permission window. Legacy full-window manual overrides remain respected. Candidate count is bounded with even coverage across the day. Completed history consumes quota but does not occupy future free time.

platform_weights is an optional dict, validated against the live provider registry. Relative 0..100 values, null removes an override, absent values use learned preferences; 0 excludes automatic allocation. Sampling is grouped by platform to avoid giving multi-account platforms extra weight. With no manual overrides the existing learned/exploration selector remains. Global weight inputs are optional numeric fields (blank is null, never zero); merge patches preserve untouched platform values. Unsaved global drafts must be saved before regenerating. AstrBotConfig persistence uses dict schema, not object.

Validation: 232 tests pass including one-window multiple rounds, rest/bounds, weighted 3:1 tendency and account-count invariance, persisted/cleared weights, failed generation preservation, concurrent task claim, manual cancellations, daily capacity, cross-midnight tail. Browser checks saved/cleared weights and clicked regeneration against real DailyPlanner/Store with a synthetic model and no live credentials: one permission window produced three real scheduled rows.
